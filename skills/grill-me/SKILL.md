# Grill Me — ZCode + Jev

本 skill 是严格规划门，目的是防止未授权实施、防止拿琐碎问题打扰用户、防止计划含糊导致返工。

## 核心执行锁：PLANNING_LOCKED

本 skill 激活即进入 `PLANNING_LOCKED` 状态。

锁定期间**禁止**：

- 编辑/写入任何文件、应用补丁、安装依赖
- 修改数据库、部署、git commit/push
- 任何有意改变项目状态的命令

锁定期间**允许**：

- 读文件、搜索、查看配置与测试、git log/status 等只读操作
- 调用 Jev 工具（jev_route / jev_grill）
- 产出与修订计划

### 解锁白名单（唯一授权方式）

| 方式 | 效果 |
|---|---|
| 用户明确说"**开始执行**"或"按计划开始执行" | 全部计划获权 |
| 用户明确说"**执行第 N 项**" | 仅第 N 项获权 |
| ZCode 规划模式（plan mode）中用户**批准**了本 skill 产出的完整计划 | 等价于"开始执行" |

以下回复**一律不解锁**（只是讨论/认可细节）：

> 好 / 可以 / 没问题 / 就这样 / 调整一下 / 第2点换成… / 再加一个… / 继续 / 看起来可以

存在歧义时，保持 PLANNING_LOCKED。

## Phase 1 — Jev 复杂度评估

在展开大范围分析之前调用 `jev_route`，只发精简任务摘要（≤10 行，不含密钥）。

向用户展示：

```
Jev 任务评估：
- 推荐等级：quick / medium / high / xhigh
- Confidence：…
- 等级是否匹配：…
```

等级排序：`quick < medium < high < xhigh`。若当前会话推理强度低于推荐等级，提示：

> ⚠ 当前推理等级低于 Jev 推荐等级，建议提升后再执行。

**离线回退**：返回 `jev: "offline"` 时，按 `fallback_advice` 自行定级并向用户注明"Jev 离线，自行判定"。

## Phase 2 — 只读调查

提问之前先查仓库。能从源码、配置、README/docs、测试、schema、部署文件、git 历史中确定的技术事实，**不许问用户**。保持 PLANNING_LOCKED。

## Phase 3 — 生成候选问题

仅当答案会**实质改变**以下内容时才生成候选问题：

业务规则 / 架构 / 实现行为 / 兼容性 / 安全策略 / 破坏性行为 / 验收标准

每个候选问题先自备四要素：

1. 问题本身
2. 推荐答案
3. 推荐理由
4. 不同选择的影响

**每个呈现给用户的问题必须带推荐答案。**

## Phase 4 — 批量 jev_grill 过滤（强制）

所有候选问题**一次性批量**送 `jev_grill`（`questions` 传 JSON 数组，每项 `{question, recommendation}`），不要逐条调用。

按返回的 `classification` 处置：

| 分类 | 处置 |
|---|---|
| `inspect_code` | 不问用户，回 Phase 2 自己查代码解决 |
| `infer_safely` | 不问用户，采用推荐值并作为假设写入计划 |
| `unnecessary` | 丢弃 |
| `duplicate` | 丢弃 |
| `ask_user` | 可以呈现给用户（见 Phase 5） |

推荐答案校验（`recommendation_check`）：

- `revise` → 先修正推荐，再重新过一遍 jev_grill，不把弱推荐当定论
- `no_safe_default` → 呈现时写明"推荐：不预设默认值，由你明确决定"

**离线回退**：`jev: "offline"` 时按其 `fallback_advice` 自行做同样规则的过滤，并在呈现问题时注明"Jev 离线，由我自行过滤"。

## Phase 5 — 呈现问题

只呈现 `ask_user` 的问题，优先用会话的提问工具（AskUserQuestion；当前环境没有该工具时，退化为"### Q1 + **推荐：** + 影响对比"的编号文本形式）：

- 推荐选项放第一位，标签加"（推荐）"
- 每问 ≤4 个选项；一次 ≤4 问，超过则收敛或分批
- 正常不超过 5 问

无阻塞问题时声明："没有必须由你确认的阻塞问题。"——但**不得**开始实施。

## Phase 6 — 完整编号计划

获权之前必须产出覆盖全部范围的计划，格式：

```
## 完整执行计划 vN

### 1. <任务>
- 目标：
- 涉及文件/模块：
- 主要修改：
- 验证方式：

### 2. <任务> …

## 风险
## 验收标准
## 测试方案
```

禁止用"进行相关调整 / 完善代码 / 处理其他问题"这类模糊话术藏工作项，每项必须具体。

## Phase 7 — 强制执行门

计划呈现后，始终以下面这段收尾：

> 🔒 当前状态：仅规划，尚未授权执行。
> 如确认完整计划，请明确回复 **开始执行**；
> 如果只希望执行某一项，请回复 **执行第 N 项**。

## 计划修订规则

用户在执行授权前改动任何需求：

1. 保持 PLANNING_LOCKED
2. 更新任务理解；范围实质变化时重跑 `jev_route`
3. 受影响的新问题重新过 `jev_grill`
4. 产出**新版本**计划（v2、v3…）
5. 重新等待明确授权

**计划调整永远不等于执行授权。**

## 执行阶段

获权后：`PLANNING_LOCKED → EXECUTION_AUTHORIZED`，然后：

- 用 TodoWrite 建任务清单跟踪进度
- 严格执行批准的计划，授权"第 N 项"时不得顺手做未授权项
- 危险操作（DROP/TRUNCATE/大量 DELETE/大量文件删除/force push/生产变更）前调 `jev_risk`，`dangerous=true` 必须先获用户显式确认
- 实施中发现计划外的实质性新需求：**停下**，回到 PLANNING_LOCKED，说明新发现、为什么超范围、建议下一步，修订计划后重新等授权
- 收尾按 `jev-complete` skill 过完成门
