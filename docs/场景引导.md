# 场景引导（通用地图，固定不按仓库改）

> 本页四条规则对所有接入仓库一致；每个仓库的差异化覆盖（极简任务例子、危险操作清单、证据规范指向）
> 写在该仓库 `AGENTS.md` 的 Jev 节里（用 `templates/AGENTS-jev.overlay.md` 实例化）。

## 四条通用规则

1. **极简任务直接做，不调用 Jev。** 什么算极简以该仓库 overlay 里的例子为准（通常是：改文案、改一个常量、改注释、小型单文件修改、简单明确的查询）。

2. **非琐碎任务先 `jev_route`。** 拿到等级后按该仓库的适用性结论决定是否进入 `grill-me` 规划门。等级结果与仓库已有任务分级（如有）叠加使用，Jev 是输入信号不是最终裁决。

3. **危险操作前 `jev_risk`。** `dangerous=true` 必须用户显式确认后才执行；`dangerous=false` 也不豁免仓库自身的确认规范（如数据库变更确认）。离线时从严自行判定。

4. **测试用 `jev-test` 取最小证据集，宣布完成前过 `jev-complete`。** 证据以该仓库已有测试/证据规范为准，`jev-test` 只做检查点与证据取舍；完成门与该仓库变更控制要求（影响范围/风险/回滚）对账。

## 离线行为（所有门一致）

Jev 返回 `{"jev": "offline"}` 时按其 `fallback_advice` 自行判定，并在给用户的结果中注明"**Jev 离线，自行判定**"，不要反复重试。密钥护栏仍生效：任何情况下不向 Jev 发送密钥。

会话/子智能体白名单里用全名：`mcp__jev__jev_route` / `mcp__jev__jev_grill` / `mcp__jev__jev_review` / `mcp__jev__jev_risk` / `mcp__jev__jev_complete`。
