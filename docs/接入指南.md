# 接入指南（评估通过之后怎么落地）

> 前置：目标仓库已有填好的 `docs/jev-adoption.md` 且结论不是"不接入"。
> 安装命令清单见工具包 `README.md`，本文只讲**作用域怎么选**和**在真实仓库里怎么验**。

## 作用域选择（按这个顺序做）

### 1. MCP 放用户级

`~/.zcode/cli/config.json` → `mcp.servers.jev`，密钥只放这里。

- 业务仓库**不提交** `.zcode/config.json` 里的 jev server——避免把命令路径和密钥带进团队仓库
- 多个仓库共用同一个用户级 MCP，零重复配置

### 2. 规则放仓库级

把 `templates/AGENTS-jev.overlay.md` 实例化成该仓库 `AGENTS.md` 里的一节，**只写评估启用的那几扇门**：

- 不要把整份 `AGENTS-jev.md` 追加到 `~/.zcode/AGENTS.md`（全局注入每个仓库每次会话）
- 多个仓库都评成四门全开、条目稳定后，再考虑把最通用的几条收到用户级
- overlay 必须写明与该仓库已有规范（分级/变更控制/测试规范）的映射关系，Jev 不覆盖仓库规范

### 3. Skill 看复用范围

| 场景 | 放哪 |
|---|---|
| 只有这一个仓库用 | 该仓库 `.agents/skills/`（复制工具包 `skills/` 下启用的门对应的 skill） |
| 多个仓库共用 | `install.ps1 -InstallSkills` / `install.sh --install-skills` 装到 `~/.agents/skills/` |

装之前检查 `~/.zcode/skills/` 有没有同名目录——那一层扫描顺序更靠前，会**遮蔽** `.agents` 的副本。
只接风险门/没开规划门的仓库**不装 `grill-me`**。

### 4. 验收三件事

1. 工具包冒烟仍是 **20 项全 PASS**（`python scripts/smoke_test.py`）
2. ZCode 里 `jev` 已连接且有 5 个工具（Settings → MCP）
3. 在目标仓库里用真实任务各试一次：
   - **极简改动**（改文案/常量）→ 从结果侧确认没产生 Jev 调用（看会话里有没有 `jev_route` 返回、或 defapi/OpenRouter 的 usage 记录），而不是只听模型说没调
   - **多文件需求** → 只触发评估启用的门，规划产出的计划落在该仓库已有的计划位置（如 `docs/plans/`）
   - 哪条门老是误触发 → 改该仓库 overlay 的项目覆盖（极简任务例子、危险操作清单），**不改工具包默认规则**

### 5. 登记台账

接入完成后在工具包 `README.md` 的"已接入仓库台账"加一行（仓库、位置、结论、启用的门、评估与复评日期）。
原因：结论文件在目标仓库深处（`docs/jev-adoption.md`），浅层扫描和子智能体常常够不到——
台账让所有实例在工具包这一层即可发现（2026-09-28 Cursor 深扫 5 层找不到试点实例的实际教训）。

- 用户级 MCP：删 `~/.zcode/cli/config.json` 里 `mcp.servers.jev` 项
