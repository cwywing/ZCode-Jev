# Jev Complete — ZCode

本 skill 是最终完成门，防止：

- 过早宣布"完成"
- 遗忘计划项
- 改动未测试
- 范围悄悄缩水（silent scope loss）
- 只测 happy path 就自信满满
- 明知有问题还宣布完成

Jev 是额外的审查者，**不替代**测试与直接证据。

## 1. 触发条件

适用于实质性任务：多文件改动 / 数据库变更 / 安全敏感 / 基础设施与部署 / 复杂调试 / 重构 / 影响生产的配置 / 大范围巡检修复 / 经 `grill-me` 规划的工作。

琐碎小改动不要求重量级完成审计。

## 2. 恢复被批准的真实范围

判定完成前，按优先级重建实际获批范围：

1. 用户最新的明确要求
2. 最新批准的 grill-me 计划
3. 明确的执行范围（如"执行第 N 项"）
4. 之后用户批准的变更
5. 验收标准
6. 项目特定要求

用户已修订需求时**不得**沿用旧计划。只授权了第 N 项时，不得把未执行项算作完成。

## 3. 建完成台账

对每个获批需求/计划项分类：`DONE / PARTIAL / NOT_DONE / BLOCKED / OUT_OF_SCOPE`，并记录：

需求 / 实现结果 / 涉及文件模块 / 执行的测试 / 证据 / 未解决问题

每个重要 DONE 项都应有支撑验证。

## 4. 核查实现现实

不要只信记忆，尽量直接查当前状态：

- `git diff` / `git status`、变更文件清单
- 测试、配置、构建产物、迁移文件
- 部署结果、相关日志

确认预期修改**确实存在**，也确认**没有夹带**未预期的改动。

## 5. 与 jev-test 结果对账

若用过 `jev-test`，消费其最新结果。逐项检查：

- 测了吗？过没过？证据合适吗？
- 关键路径是否还停在 PARTIALLY_VERIFIED？
- 有没有 BLOCKED？有没有未解释的失败测试？

**代码写了 ≠ 需求安全地 DONE。**

## 6. 强制 jev_complete

宣布实质性任务完成前调用 `jev_complete`，state 提供精简但完整的摘要：

用户批准的目标 / 编号计划（如有）/ 实际修改 / 已执行测试 / 关键证据 / 失败与跳过的测试 / 未解决项 / 已知风险 / 明确的范围外项

**不发密钥。** 把返回的 completed / probability / thoroughness 作为独立信号。

**离线回退**：`jev: "offline"` 时按其 `fallback_advice` 自行判定（逐项核对批准范围、关键路径证据、未解释失败；任何存疑降级为 PARTIAL），并在结论中注明"Jev 离线，自行判定"。

## 7. 完成决策四态

- **COMPLETE**：授权的关键需求全部 DONE；必须的测试通过；无未解决的关键问题；证据充分；无计划项被悄悄跳过；Jev 信号支持完成。
- **COMPLETE_WITH_NOTES**：核心工作完成；仅剩明确非关键的局限；局限已清楚披露且不违反验收标准。**禁止**把缺失的必备功能伪装成"备注"。
- **PARTIAL**：有实质进展，但仍有未完成的需求项。
- **BLOCKED**：完成依赖不可得的外部条件（凭证/环境）、需要用户决策、或无法安全验证。

正确状态是 PARTIAL 或 BLOCKED 时，**不得**使用 COMPLETE。

## 8. Jev 不同意时

自评为 COMPLETE 但 Jev 明确反对时：**不要**立即宣布完成，先调查其关切——缺测试？漏计划项？证据不足？失败路径？恢复路径？未验证假设？

- 关切成立 → 修复或如实报告
- 关切确实无关 → 记录理由后按实际证据继续

Jev 是顾问，不是不容置疑的权威。

## 9. 完成检查中发现范围外需求

发现获批计划之外的新实质需求：**不要**悄悄顺手实现。

若 `grill-me` 在管：回到 PLANNING_LOCKED，说明新发现是什么、为何超范围、建议下一步；必要时修订计划并重新等待执行授权。

## 10. 最终响应格式

实质性任务用以下格式收口：

```
# 完成检查

## Jev
- 完成判断：
- Confidence / Probability：
- 主要关注点：

## 计划执行情况

### 1. <计划项>
- 状态：DONE / PARTIAL / NOT_DONE / BLOCKED
- 修改：
- 验证：
- 证据：

### 2. <计划项> …

## 测试
- 通过：
- 失败：
- 未执行：
- 阻塞：

## 遗留问题
- 无 / 具体列出

## 最终状态
**COMPLETE** / **COMPLETE_WITH_NOTES** / **PARTIAL** / **BLOCKED**
```

只有实际证据支撑时才能写 COMPLETE。
