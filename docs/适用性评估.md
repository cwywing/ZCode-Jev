# 适用性评估（Jev 接入门控）

> 本文档属于 `ZCode-Jev` 工具包。评估方法在这里，评估**结论**写进目标仓库的 `docs/jev-adoption.md`（用 `templates/jev-adoption.md`）。
> 硬规则：**没有写进目标仓库的适用性结论，就不改那个仓库的 `AGENTS.md`。**

## 为什么先评估

全局规则会进每个仓库的每次会话。Jev 的四扇门（规划 grill / 开工 route / 风险 risk / 完成 complete）不是每个仓库都需要——对只改文案的仓库，规划门是纯负担；对无人值守流水线，"等开始执行"的锁根本走不通。先评估，再按结论接门。

## 六件事评估清单

| # | 看什么 | 偏向"接"的信号 | 偏向"不接"的信号 |
|---|---|---|---|
| 1 | 非琐碎任务占比 | 多文件功能、疑难缺陷、架构/数据库/安全改动多 | 几乎都是文案、单文件小改、一次性脚本 |
| 2 | 必须人拍板的决策 | 有业务规则分叉、方案选型、验收标准争议 | 需求都直接明确，无澄清空间 |
| 3 | 已有计划/测试证据规范 | 有（Jev 门**叠加映射**到现有规范，不另写一套） | 无（Jev 门提供默认结构） |
| 4 | 成本与延迟容忍 | 能接受每个非琐碎任务多几次廉价调用 | 完全不可接受额外调用/密钥费用 |
| 5 | 不可逆操作 | 有迁移、清库、生产配置、force push | 无 |
| 6 | 验收方式 | 靠界面/接口/数据取证（不是只看 diff） | 只看 diff 即可 |

另有硬前提：任务流程能停下来等人（"开始执行"确认）。无人值守/不能停的流程 → 至多只接风险门。

## 四档结论（预设组合，可逐门调整）

| 结论 | 门组合 | 适用 |
|---|---|---|
| **不接入** | 无 | 六件事几乎全偏"不接"；或任务无人值守 |
| **只接风险门** | risk | 有不可逆操作，但日常改动不值得规划/完成门 |
| **开工 + 收工** | route + complete（+risk 如有危险操作） | 多文件功能多、发布频繁，但澄清问题少 |
| **四门全开** | route + grill + risk + review/test + complete | 架构、数据库、安全、需留证据的界面/接口，且有人拍板 |

四档只是起点：结论表里的"实际启用的门"逐门勾选（如"开工+收工"仓库后来出现危险操作，单独加 risk 门即可，不必换档）。

## 硬规则

1. **没密钥不开规划门和完成门。** 离线时 Jev 只剩流程没有判断，这两扇门的开销白付（风险门离线仍可从严自判，可保留）。
2. **只接风险门的仓库不装 `grill-me`。** 否则中等任务可能被锁进 PLANNING_LOCKED。
3. **已有规范叠加不另写。** 仓库里已有分级/变更控制/测试规范的，overlay 里写映射关系（例：`jev_route` 结果作为现有分级的输入信号），Jev 不覆盖仓库规范。
4. **结论写进目标仓库**（`docs/jev-adoption.md`）：结论、逐门勾选、理由、密钥状态、复评日期。
5. **复评**：默认每季度，或仓库性质重大变化时（如从原型转生产）。

## 评估产出流向

```
本文档（方法） ──填写──▶ 目标仓库 docs/jev-adoption.md（结论）
                              │
                              ▼
                     接入指南（按结论落地 MCP/规则/skill）
                              │
                              ▼
                     AGENTS-jev.overlay（贴进该仓库 AGENTS.md 的一节）
```
